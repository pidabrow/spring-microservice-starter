# AGENTS.md

Cross-tool entry point for coding agents working in this repository.
Read in this order:

1. **`CLAUDE.md`** — architecture, code conventions, autonomy policy. Applies
   to every agent regardless of tool, despite the file name.
2. **`docs/delivery/CONVENTION.md`** — how a change is delivered: identifiers,
   folder layout, artifact contract per change type, gates, evidence, lint rules.
3. **`docs/adr/`** — why the architectural decisions were made (MADR 4.0).

## Roles

Persona definitions live in `docs/delivery/agents/` as the single source of
truth. Tool adapters in `.github/agents/` (Copilot) and `.claude/agents/`
(Claude Code) are **generated** — edit the source and run `chg sync-agents`.

| Persona | Produces |
| --- | --- |
| `analyst` | `analysis.md` / `diagnosis.md` / `brief.md`, `spec.md` |
| `tester` | `test-plan.md` |
| `developer` | code, `implementation.md` / `findings.md` |

## Non-negotiables

- Artifacts are written with `status: draft`. Approval is a human command
  (`chg approve`), never an edit by an agent.
- The test contract is committed before production code.
- Evidence is generated by `chg evidence`. Agents write only the
  `## Interpretation` section; they never state a result they did not measure.
- A persona does not edit another persona's artifact. It reports the problem.
- Deterministic work (identifiers, folders, branches, evidence collection)
  belongs to `chg`, not to a prompt.

## Commands

```
chg new --type feat --title "..."   scaffold a change: issue, folder, branch
chg approve <ref> <artifact>        stamp a human gate
chg lint [--strict] <ref>           validate against the convention
chg evidence <ref>                  collect proof from the build and CI
chg status <ref>                    show artifacts and their state
chg sync-agents                     regenerate the tool adapters
```
