# Change Delivery Convention

The contract every change in this repository follows, whether written by a human
or by an agent. Tool-neutral by design: this file is the source of truth, and
`.github/agents/` plus `.claude/agents/` are generated adapters.

Related: [ADRs](../adr) record *why* decisions were made; this document records
*how* a change is delivered.

## Vocabulary

One word per concept. The same word appears in the CLI, in artifact frontmatter,
in persona definitions and in lint messages. If three names exist for one thing,
nobody (agent included) can tell whether they are synonyms.

| Concept | Word |
| --- | --- |
| Identifier of a unit of work | `workItemRef`, shaped `<TRACKER>-<ID>` (`GH-42`, `PDEV-123`) |
| Type of change | `feat`, `fix`, `chore`, `spike` |
| Document produced in the flow | `analysis`, `diagnosis`, `brief`, `spec`, `test-plan`, `implementation`, `findings`, `evidence` |
| Artifact state | `draft`, `approved` |
| Role | `analyst`, `tester`, `developer` |

## Layout

```
docs/changes/GH-42-outbox-retry/
  analysis.md         analyst    context, questions and answers, out of scope
  spec.md             analyst    requirements + acceptance criteria
  test-plan.md        tester     cases derived from the spec, BEFORE the code
  implementation.md   developer  execution note, deviations from the spec
  evidence/
    evidence.md       generated by `chg evidence`, never written by an agent
    junit/ coverage/
```

No `YYYY-MM` nesting: tracker IDs increase, so folders already sort
chronologically. Branch: `<type>/<workItemRef>-<slug>`, e.g.
`feat/GH-42-outbox-retry`. The slug is derived once, by the tool, and reused in
all three places.

## Artifact contract per type

A `type` exists only when it implies a different artifact contract. If two values
would require the same files, the same starting persona and the same kind of
proof, they are one value with two names.

| `type` | first artifact | spec | test-plan | proof |
| --- | --- | --- | --- | --- |
| `feat` | `analysis.md` | yes | yes | full set |
| `fix` | `diagnosis.md` | no, the spec does not change | regression test | red → green |
| `chore` | none | no | no | green CI |
| `spike` | `brief.md` | no | no | `findings.md` + a decision |

`feat`, `fix` and `chore` come from Conventional Commits and carry versioning
semantics. `spike` is a mode of work rather than a delta in the product; it lives
in the same field deliberately, so that stepping outside the flow is explicit
rather than invisible.

Commit messages use the full Conventional Commits vocabulary (`refactor`, `perf`,
`docs`, `test`, `build`, `ci`). Two dictionaries, two levels: four change types,
all commit types.

## Frontmatter

```yaml
---
workItemRef: GH-42
artifact: spec
type: feat
version: 1
status: draft
persona: analyst
links:
  issue: https://github.com/owner/repo/issues/42
  branch: feat/GH-42-outbox-retry
  pr: null
  ci_run: null
approved_at: null
approved_by: null
---
```

`version` starts at 1 and is bumped only when an approved artifact is edited.
Everything else is git's job.

## Gates

Approval is a command, not an edit: `chg approve GH-42 spec`. An agent may only
ever write `status: draft`. The command stamps the status, the timestamp and the
author, so the gate leaves an auditable trace instead of a line of text any
agent could have typed itself.

| `type` | gated artifacts |
| --- | --- |
| `feat` | `analysis`, `spec`, `test-plan` |
| `fix` | `diagnosis`, `test-plan` |
| `chore` | none |
| `spike` | `brief` |

A gate after every phase is calibration mode. Once the flow has run on a handful
of changes, tier it by risk and let `chore` out of the flow entirely.

## Evidence

Evidence is machine-produced or it is not evidence. `chg evidence` collects the
commit SHA, the CI run URL and its conclusion, JUnit XML and coverage reports.
An agent may write only the `## Interpretation` section. Prose saying "all tests
passed" proves nothing.

Standard formats are used deliberately: JUnit XML for results, SARIF for static
analysis, and GitHub artifact attestations for build provenance. `evidence.md` is
an index over those, not a format of its own.

## Lint rules

`chg lint <ref>` locally, `chg lint --strict <ref>` in CI, where warnings become
errors. A prompt is a request; a schema is a contract.

| Rule | Check |
| --- | --- |
| R1 | The change folder exists and matches the branch name |
| R2 | The artifact set required by this `type` is complete |
| R3 | Every frontmatter header satisfies the schema |
| R4 | One `workItemRef` across artifacts, branch and folder |
| R5 | The test contract was committed before production code |
| R6 | Evidence exists and links to a CI run and a commit |
| R7 | No approved artifact changed without a version bump |

R5 is the only mechanical guarantee that tests come from the requirement rather
than from the code. For a `fix` the equivalent is a regression test that fails
before the fix: a falsifiable hypothesis about the cause. If a deterministic
failing test is genuinely impractical (race conditions, environment-dependent
behaviour), record the reason and the alternative proof in a
`## Test deviation` section of `diagnosis.md`, so the gap is visible in the diff
rather than silent.

## Flow

```
chg new --type feat --title "..."      issue -> workItemRef -> folder -> branch
  analyst     -> analysis.md, spec.md        chg approve GH-42 spec
  tester      -> test-plan.md                chg approve GH-42 test-plan
  developer   -> code + implementation.md
chg evidence GH-42                     collect proof
chg lint --strict GH-42                gate before the PR
```

The issue is the *output* of refinement, not its input. Sharpen the title and
scope first, then create it, so the ID is stamped on something real.

## Relation to other standards

This layout is deliberately close to [GitHub Spec Kit](https://github.com/github/spec-kit)
so that its tooling stays adoptable without migration. Two differences:
identifiers come from the tracker rather than a local counter, and the flow does
not stop at implementation — the evidence layer closes the loop Spec Kit leaves
open.
